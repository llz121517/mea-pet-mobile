# 版本迁移模块 · 纪律

本包是**长期保留的版本迁移基础设施**：总入口 [LegacyMigration] 与 [LegacyMigrationStep] 接口会一直存在；`steps/` 下的**具体迁移步骤**是一次性代码，到期单独删除。所有改动必须遵守：

1. **一个迁移操作一个文件**：放在 `steps/` 下，实现 `LegacyMigrationStep`，并注册到 `LegacyMigration.STEPS`。
2. **step 顶部必须写明**：预计移除版本、被引用点；没有移除计划的不允许合入。
3. **只做「检测旧数据 → 删除 / 重置 / 迁移」**：不得新增业务功能，不得依赖新功能代码，不得借机塞入其它需求。
4. **业务代码禁止直接引用本包**：唯一调用方是 `AppContainer.warmUp()`；组件之间不得通过本包通信。
5. **每步必须幂等**：可重复执行；失败只记日志，不阻塞启动、不影响其它步骤。
6. **迁移命中时必须同步收敛状态**：例如清理旧版 TTS 数据后，要一并关闭主界面/悬浮窗两个语音开关，避免出现"开关开着但模型不在"的错觉。
7. **新增迁移的固定动作**：`steps/Xxx.kt` + 注册 `STEPS` + JVM 单测（临时目录 / mock），不修改业务模块。
8. **删除只删单个 step**：到该 step 的预计移除版本，删掉对应文件、`STEPS` 注册项、测试与 `docs/legacy-compat.md` 对应条目；**总入口与接口保留**。
