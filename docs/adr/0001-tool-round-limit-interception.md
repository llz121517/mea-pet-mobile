# ADR 0001：工具轮次用尽时在工具执行端拦截，不发送 `tool_choice="none"`

- 状态：已采纳（2026-11-19，1.9.0 dev）
- 相关代码：`ChatToolLoop`

## 背景

工具循环达到轮数上限时，若把某一轮的 `tool_choice` 设为 `"none"` 来强制收尾，模型会因「想调用工具却被禁止」而把内部工具调用标记当作正文输出（用户看到 `<｜｜DSML｜｜…>` 之类的乱码）。这种形态因模型与网关而异，客户端无法用文本匹配穷举。

## 决策

工具循环全程保持 `tools` + `tool_choice: "auto"`，绝不发送 `"none"`。轮次用尽后由**工具执行端**拦截：调用不执行，只回填一条 `tool_round_limit` 的 tool 结果（明确提示模型直接回答）；若模型仍不产出正文，允许有限个拦截轮后如实失败并回滚整轮。

## 后果

- 不再制造「禁止调用」状态，从根上移除该泄漏的诱因；请求协议全程一致，前缀缓存不受影响。
- 移除按厂商 token 格式匹配的文本清洗（`ToolCallMarkup`），不再维护格式白名单。
- 极端情况多 1~2 次请求；拦截轮的消息照常入历史（`tool_calls` 与 tool 结果成对）。
