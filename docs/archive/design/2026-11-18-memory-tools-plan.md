# 1.9 记忆系统：当前实现参考

> 状态：**已接入（1.9.0 dev）**。本文记录当前模式行为、兼容边界和实现参考。发布前仍需真机验收，见 [`TODO.md`](../../TODO.md)。

## 1. 检索模式

设置项保留 `AUTO`、`TOOLS`、`TEXT`、`OFF` 四个枚举值。`TEXT` 是兼容模式名，不代表通过回复文本写入记忆；界面可将其标注为只读。

| 模式 | 行为 |
|---|---|
| `AUTO` | 优先将记忆工具提供给模型；若聊天端点不支持工具调用，回退为只读关键词检索与注入。 |
| `TOOLS` | 通过工具检索、创建、更新和删除记忆；端点拒绝工具调用时，为保持聊天可用也回退为只读关键词注入。 |
| `TEXT` | 只执行关键词检索与上下文注入，不创建、更新或删除记忆。 |
| `OFF` | 不注入或检索记忆，已保存的记忆仍保留。 |

记忆总开关关闭时，不提供记忆工具或记忆上下文。联网工具由联网开关独立控制，在上述四种模式和记忆总开关关闭时均可使用；`TEXT` + 联网仍保留只读关键词注入。记忆工具在执行与提交时再次检查开关，轮次中关闭记忆后不执行后续记忆操作，也不提交暂存变更。

## 2. 只读关键词注入

`TEXT` 以及 `AUTO` / `TOOLS` 在不支持工具调用时的回退均为只读路径：

- 根据当前输入检索关键词命中项，并将结果附加到发往模型的最后一条 user 消息副本 / 本轮 tail；不修改已经保存的用户消息或会话历史。
- `buildContext` 仅构造待发送内容，不修改记忆；只读命中不更新访问计数或访问时间。
- 此路径不会创建、更新、删除记忆，也不会触发自动摘要。人设中稳定的事实 / 特质记忆引用仍保留。
- 工具端点能力回退只改变请求构造；SQLite 会话与记忆数据不会因切换到文本模式或回退而清理。

## 3. 工具模式与提交

支持工具调用时，模型可使用 `search_memory`、`create_memory`、`update_memory`、`delete_memory`：

- `search_memory` 只读；检索包含已落库记忆与当前轮待提交变更，关键词、内容、重要度和新近度用于排序。
- `create_memory` 仅允许 `SHORT_TERM`、`CORE_TRAIT`、`FACTUAL`；`LONG_TERM` 由独立摘要流程维护。
- 新建、更新和删除先在当前 turn 暂存；正常成功完成的记忆工具轮次提交变更。失败、取消或超时会丢弃未提交变更。工具循环已经产生记录后再被 HTTP 错误拒绝，整轮失败并回滚，不重新走只读降级，也不把错误缓存为缺少工具能力。
- 删除 `FACTUAL` / `CORE_TRAIT` 需要明确确认；已提交的删除可通过快照撤销。
- 成功的记忆工具模式轮次可按设置独立触发自动短期到长期记忆摘要。文本模式、关闭模式、只读回退及仅启用联网工具的轮次不触发记忆提交或自动摘要。

## 4. 会话历史、存储和兼容

工具循环中的 assistant `tool_calls` 与 `tool` 结果保留在会话历史中，并按 `turn_id` 处理。构造请求时，是否回放工具历史由本轮实际启用的工具协议决定：纯文本请求 / 不支持工具的回退过滤结构化工具消息，`TEXT` + 联网仍保留工具历史；SQLite 中的原始记录不变。

SQLite 是当前会话和记忆存储。兼容升级遵循非破坏原则：

- 旧 JSON 会话中遗留的记忆操作字段在读取时忽略，不参与对话或记忆处理。
- 新建数据库不再创建旧的记忆操作 nullable 列。已有开发期数据库中的该列保持不动、忽略读取，不执行破坏性迁移。
- 现有记忆数据、稳定人设引用、工具写入和撤销行为不受只读模式影响。

相关存储与会话实现背景见 [`2026-11-18-sqlite-context-plan.md`](2026-11-18-sqlite-context-plan.md)。

## 5. 能力缓存与验证

- 仅在首个工具请求明确被拒绝为不支持工具能力时，退回只读请求并记录当前连接的负缓存；普通 HTTP 错误不据此禁用工具。
- API 地址、Key 或模型变化会使负缓存失效，下一轮重新尝试工具，不必重启进程。
- 自动摘要与上下文压缩是不同功能：自动摘要维护记忆，只在成功记忆工具模式轮次后运行；上下文压缩整理发给模型的会话历史。
